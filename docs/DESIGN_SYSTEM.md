# Pomateshe — Принципы дизайн-системы

Статус: принципы и токены-категории для будущей реализации UI. **UI не создаётся в рамках
этой задачи** — документ фиксирует, как проектировать интерфейс, когда придёт фаза реализации,
и на какие установленные skills опираться (`ui-ux-pro-max`, `design-taste-frontend`,
`frontend-design`).

## 1. Какие skills применять и когда

- `design-taste-frontend` — при проектировании публичных страниц преподавателей (лендинги,
  анти-шаблонный, "не выглядит как типовой AI-дизайн") и при редизайне текущего `index.html`
  в будущем.
- `ui-ux-pro-max` — при построении личных кабинетов (дашборды, таблицы, формы) — источник
  палитр, типографики, чек-листов доступности и UX-паттернов для табличных/дашборд-интерфейсов.
- `frontend-design` — общий ориентир качества при реализации любых компонентов.
- `code-reviewer` — код-ревью реализованных компонентов (после появления кода).

Ни один из них не применяется в этой задаче — они зафиксированы здесь как решение "какой
skill за что отвечает" на будущее, чтобы не переизобретать выбор на каждой фазе.

## 2. Публичная страница преподавателя vs личный кабинет — разный характер дизайна

- **Публичная страница** — маркетинговый лендинг конкретного преподавателя: должна отражать
  его предмет/стиль, не быть "одним шаблоном на всех" (см. `design-taste-frontend`: audit-first
  на редизайне, читать бриф, не дефолтный AI-стиль). Preact-серверный рендер, минимум JS.
- **Личный кабинет (teacher/student)** — рабочий инструмент: приоритет предсказуемости,
  плотности информации, скорости, а не "вау-эффекта". Единая, скучная в хорошем смысле,
  дизайн-система для всех кабинетов независимо от того, какой преподаватель.

## 3. Токены (категории, без конкретных значений — подбираются в фазе реализации)

- **Цвет**: нейтральная база (фон/текст/границы) + один акцентный цвет бренда `pomateshe`
  (уже есть в текущем `index.html`: индиго `#4f46e5`/`#6366f1` — переиспользуется как отправная
  точка, а не изобретается заново, если не будет отдельного решения о ребрендинге) + семантические
  цвета состояний (успех/ошибка/предупреждение/инфо) с проверкой контраста ≥ 4.5:1
  (см. `ui-ux-pro-max`: `color-contrast`).
- **Типографика**: одна основная гарнитура для UI (в текущем прототипе — Inter, сохраняется как
  умолчание), минимальный размер текста 16px на мобильных (`readable-font-size`), line-height
  1.5–1.75 для основного текста.
- **Отступы/сетка**: единая шкала (4px/8px база), брейкпоинты — mobile-first, обязательна
  проверка отсутствия горизонтального скролла на узких экранах.
- **Тёмная тема**: сохраняется как требование — в текущем прототипе уже реализована
  (`darkMode: 'class'` в Tailwind config) — новая платформа не должна быть шагом назад.

## 4. Доступность (обязательный baseline, не "добавим потом")

- Touch target ≥ 44×44px (критично для мобильных учеников).
- Видимые focus-states на всех интерактивных элементах.
- `aria-label` для icon-only кнопок, `label[for]` для всех полей форм.
- Табуляция соответствует визуальному порядку.
- `prefers-reduced-motion` учитывается в анимациях.
- Иконки — SVG, не эмодзи (консистентность на всех платформах/ОС).

## 5. Компонентный инвентарь (список, не реализация)

Кабинеты потребуют: таблицы (ученики/занятия/платежи), календарная сетка/список расписания,
карточки учеников, модальные окна (создание/редактирование), формы с валидацией (zod на клиенте
зеркалит серверную схему из `docs/API.md`), загрузчик файлов с прогрессом, canvas-доска
(отдельная зона, см. `docs/WHITEBOARD.md`), баннер cookie-согласия (`docs/CONSENTS.md`),
уведомления/тосты. Конкретная реализация — фаза UI (`docs/ROADMAP.md`).

## 6. Что сохраняется из текущего `index.html`

- Бренд-цвет индиго, шрифт Inter, поддержка тёмной темы, PWA-манифест (иконка/название) —
  переиспользуются как стартовая точка бренда, чтобы не терять уже узнаваемый визуальный стиль
  сайта `pomateshe.ru`, если продукт-оунер не решит иначе на этапе реализации.
